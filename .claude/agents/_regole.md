# Regole comuni agli agenti di analisi di RidePlan

- Leggi `docs/PROGETTO.md`, `README.md` e le issue aperte (`gh issue list -R NanuNic9379/RidePlan`, `gh issue view N`).
- **Solo analisi**: non modificare file, non fare commit, non commentare issue, non creare nulla su GitHub.
- Ragiona dalla tua esperienza in sella: cosa ti serve davvero, cosa ti manda in crisi delle app che usi oggi
  (Calimoto, Kurviger, Google Maps, Garmin, Komoot, Scenic, MyRoute-app, REVER, Wheelo…). Puoi cercare in rete
  recensioni e lamentele reali degli utenti per confermare.
- Rispetta i principi del progetto: niente account, niente server nostri (condivisione c2c), offline prima di
  tutto, GPX, nessuna raccolta di dati, open source GPL-3.0.
- Rapporto finale in italiano, conciso, in quest'ordine:
  1. **Chi sei** (una riga).
  2. **Per issue #1–#7**: cosa deve esserci per te (criteri di accettazione concreti), cosa evitare.
  3. **Mancanze**: funzioni assenti dal piano che per te sono decisive (massimo 5, in ordine di importanza),
     ognuna con "perché, in strada".
  4. **Priorità**: le 3 cose da fare per prime.
  5. **Rischi**: cosa ti farebbe disinstallare l'app.
